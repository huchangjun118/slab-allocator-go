# slab — 小块内存池分配器（Go）

仅依赖 Go 运行时与标准库的并发安全内存池，面向对**分配开销**与**碎片**敏感的
小块内存复用场景。不依赖任何外部服务或本机以外的资源。

## 快速开始

```go
package main

import (
	"errors"
	"fmt"

	"github.com/huchangjun118/slab-allocator-go"
)

func main() {
	p, err := slab.New(slab.DefaultConfig())
	if err != nil {
		panic(err)
	}
	defer p.ReleaseIdle()

	b, err := p.Alloc(128) // 命中 128 分级
	if err != nil {
		panic(err)
	}
	buf := b.Bytes()      // len=128, cap=128，地址按 8 字节对齐
	for i := range buf {
		buf[i] = byte(i)
	}

	if err := p.Free(b); err != nil {
		if errors.Is(err, slab.ErrDoubleFree) {
			// 重复 / 并发释放被明确拒绝
		}
	}
}
```

## 尺寸分级与块内切分

- `Alloc(size)` 返回一个 `*Block` 句柄，`Block.Bytes()` 是长度为 `size`、
  容量为所属分级尺寸的数据切片。
- 命中规则确定：`size` 被授予**第一个**满足 `Classes[i] >= size` 的分级；
  尺寸边界处的请求（`size == Classes[i]`）确定命中该级，**绝不会**被塞入
  更小的分级，也不会跨多个小块拼接。
- 超过最大分级的请求立即以 `ErrOversized` 失败——即使总空闲空间足够。
- 底层区间按“最佳适配”（最小可容纳段；同长取区间 id 更小、再取偏移更小）
  从空闲段低端切分，余段仍可继续满足更小请求。切分位置与选择结果在相同
  操作序列下完全确定。

## 复用语义（两级结构）

1. **分级 LIFO 缓存**：`Free` 的块进入其所属分级的 LIFO 空闲缓存，同分级
   后续申请按后进先出顺序复用。命中缓存只争用**该分级**的锁，不触碰全局
   结构——某一分级争用严重不会阻塞无关分级。
2. **区间空闲结构（跨分级）**：当分级缓存未命中时，在全部底层区间的空闲
   段中按上述最佳适配取段；若仍无合适段，会**一次性把全部分级缓存归位**，
   归位时立即与前后相邻的空闲段**合并**为更大的可复用区间，然后重试；
   仍无空间才按需增长新区间。

合并只发生在相互紧邻的空闲段之间，任何存活块都不会被跨越或覆盖。这套
“先缓存、分配失败再归位合并”的策略既保留了热路径的低开销，又保证长期
运行后不会出现“空闲总量足够却满足不了中等尺寸”的假耗尽。

### 复用次数口径

空闲段带有 `reclaimed` 标记：来自已归还块的段（及其合并产物）为 `true`，
从未授予过的初始段及纯切分余段为 `false`。一次申请若取自回收段，则
`Stats.ReuseCount` 加一。该口径与 map 遍历等运行时随机因素无关，在固定
操作序列下逐条一致。

## 对齐

`Config.Alignment` 为所有返回地址声明的对齐字节数，必须是 2 的幂。内部
对齐粒度取 `max(Alignment, 8)`（下限 8 用于保证 32 位平台上的 64 位原子
安全；它同样是声明对齐的倍数/约数，因此返回地址对声明对齐恒成立）。
每个区间首地址按该粒度对齐，块跨度按该粒度向上取整，故任何存活块地址
都满足声明对齐。

## 容量上限、按需增长与空闲归还

- 构造时立即建立首个 `RegionSize` 区间；耗尽后按固定策略每次增长一个
  `RegionSize` 区间。
- `MaxCapacity > 0` 时，增长会使总容量超过上限则以 **`ErrPoolExhausted`**
  失败；失败不改变任何状态，因此不会静默超发，也不会提前吞掉后续无关
  申请（释放空间后再申请照常成功）。`MaxCapacity == 0` 表示不限。
- `ReleaseIdle()` 先把全部分级缓存归位（触发合并），再把**完全空闲**
  （无存活块、空闲表覆盖整个区间）的底层区间交还给运行时（移除引用，由
  GC 回收），并至少保留一个区间。返回释放字节数。仍有存活块的区间不会
  被回收。

## 非法操作的明确拒绝

| 情形 | 返回 |
| --- | --- |
| `Free(nil)` 或句柄不属于本池 | `ErrInvalidPointer` |
| 块已被释放（含并发重复释放，原子 CAS 只有一个赢家） | `ErrDoubleFree` |
| 块在 `Reset` 之前分配、之后继续使用/释放 | `ErrUseAfterReset` |
| `Alloc(size<=0)` | `ErrInvalidArgument` |
| `size` 大于最大分级 | `ErrOversized` |
| 达到总容量上限且无法回收/增长 | `ErrPoolExhausted` |
| 配置非法 | `ErrInvalidConfig`（错误文本逐条指出越界字段） |

通过显式句柄 `*Block` 而非裸指针进行归属与生命周期判断，无需在用户数据
区前后写入内联头部，因此不存在头部被覆盖、伪造或地址 ABA 复用导致的静默
误判。

## 重置与统计

- `Reset()` 使代际号 +1，**全部**未失效块（含用户仍持有和缓存中的块）
  被标记失效：之后 `Valid()` 为 `false`、`Bytes()` 返回 `nil`、`Free`
  返回 `ErrUseAfterReset`；空闲结构归零，统计清零，底层容量保留，池可
  立即重新使用。
- `Stats()` 返回快照：

| 字段 | 含义 |
| --- | --- |
| `TotalAlloc` / `TotalFree` | 累计成功申请 / 释放次数 |
| `LiveBlocks` | 当前存活块数（不含分级缓存中的块） |
| `UsedBytes` | 当前占用，按块所属**分级尺寸**计 |
| `PeakBytes` | 历史 `UsedBytes` 峰值 |
| `ReuseCount` | 取自回收空间的申请次数 |
| `RegionCount` / `CapacityBytes` | 当前底层区间数与总容量 |

在相同的串行操作序列下，所有统计字段逐条一致。

## 配置项

```go
type Config struct {
	Alignment   int   // 返回地址对齐，2 的幂，>=1
	Classes     []int // 升序、互不相同的分级尺寸，均须为 Alignment 的倍数
	RegionSize  int   // 单区间容量（字节），须容得下最大分级
	MaxCapacity int   // 总容量上限（字节）；0 表示不限
}
```

默认配置 `DefaultConfig()`：`Alignment=8`，分级
`[16 32 64 128 256 512 1024 2048 4096]`，`RegionSize=1MiB`，
`MaxCapacity=64MiB`。

校验规则（违反即返回包装了 `ErrInvalidConfig` 的错误，**绝不静默降级**）：

- `Alignment` 必须是正的 2 的幂；
- `Classes` 至少一个，必须为正、严格升序，且每个尺寸是 `Alignment` 的倍数；
- `RegionSize` 为正，且不小于“最大分级按内部粒度取整后的跨度”；
- `MaxCapacity` 为 0 或不小于 `RegionSize`（否则首个区间都无法建立）。

## 并发模型

- 每个分级一把互斥锁；全局区间结构一把互斥锁。
- 全局唯一锁序：**先按分级下标升序持分级锁，再持全局锁**，不存在反向路径，
  因而不会发生 ABBA 死锁。
- 块状态以原子量（`live/free/dead`）维护，单块内读写在 Go 内存模型下不会
  撕裂；同一块的并发重复释放由 CAS 精确裁决为“一次成功，其余拒绝”。
